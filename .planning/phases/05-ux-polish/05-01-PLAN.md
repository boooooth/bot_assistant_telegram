## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram user → bot handler | Untrusted user message text crosses into handle_text |
| LLM provider → bot handler | LLM-generated reply text (untrusted length/content) is split and echoed back to the user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Denial of Service | split_text on an extremely long LLM reply | mitigate | `max_chunks=3` hard cap bounds work and outbound messages regardless of reply length (D-04); loop terminates because each iteration consumes >= 1 char of `remaining` or breaks |
| T-05-02 | Denial of Service | typing action fired before auth check (D-02) | accept | One fire-and-forget `send_chat_action` per inbound update adds negligible cost; no renewal loop (D-01); public-bot cost risk is already an accepted project-level decision (STATE.md blocker, OpenAI billing cap is the real control) |
| T-05-03 | Tampering | LLM reply text rendered to user | accept | Reply sent as plain text via reply_text with no parse_mode set — no Markdown/HTML injection surface; chunk boundaries are pure string slicing with no eval |
| T-05-SC | Tampering | dependency installs | mitigate | No new packages introduced — typing indicator and splitting use stdlib + already-installed python-telegram-bot; no package-manager install tasks in this plan |
</threat_model>
