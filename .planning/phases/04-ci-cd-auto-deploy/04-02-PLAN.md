<objective>
Replace the two independent workflows (`ci.yml`, `deploy.yml`) with a single
`.github/workflows/ci-cd.yml` whose `deploy` job is gated on CI passing. This closes the headline
DEP-04/QA-02 gap: today `deploy.yml` has `needs: []` and triggers independently, so deploy ships even
when CI fails. The new structure runs a `ci-checks` job on every push + PR, then a `deploy` job that
`needs: [ci-checks]` and only runs `if: github.ref == 'refs/heads/main'`. It also fixes two deploy
correctness/security bugs: the `:latest` no-recreate bug (use `--pull always --force-recreate`) and the
revoked-token GHCR login (remove the in-script `GITHUB_TOKEN`).

Purpose: "CI proves the code is good; CD ships it" expressed as two jobs in one DAG — deploy only on green,
only on main. Reuse the existing, proven build/push + appleboy SSH steps.
Output: `.github/workflows/ci-cd.yml` (new combined workflow); `.github/workflows/ci.yml` and
`.github/workflows/deploy.yml` deleted.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fork PR → CI runner | Untrusted PR code runs in `ci-checks`; must never reach secrets or the deploy step |
| GitHub Actions runner → VPS (SSH) | Deploy commands cross from CI into the live server over SSH |
| CI runner → GHCR | Image push authenticated with the job `GITHUB_TOKEN` (build side only) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | deploy of unverified code (CI bypass) | mitigate | `deploy` job `needs: [ci-checks]` — deploy only runs on a green CI; this is the core DEP-04/QA-02 fix |
| T-04-02 | Information Disclosure | GITHUB_TOKEN leaked into remote process list/history via SSH `script:` | mitigate | Remove the in-script `docker login` with `secrets.GITHUB_TOKEN`; server-side GHCR auth handled durably (Plan 03 checkpoint: public package or one-time read-only login) |
| T-04-03 | Information Disclosure | Fork PR exfiltrates secrets | mitigate | `deploy` guarded by `if: github.ref == 'refs/heads/main'`; deploy steps never run for PRs; `ci-checks` uses no secrets |
| T-04-04 | Tampering | Unpinned third-party actions run untrusted code | mitigate | Pin actions/checkout@v4, setup-python@v5, login-action@v3, build-push-action@v6, ssh-action@v1 to release tags |
| T-04-05 | Denial of Service | Two pollers on one token during release (409) | accept/mitigate | Keep default Compose stop-old-then-start-new via `--force-recreate`; do NOT add blue-green/start-first; verified in Plan 03 checkpoint |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No NEW third-party runtime packages this phase; dev-tooling additions (ruff, mypy) are first-party, audited OK in RESEARCH Package Legitimacy Audit — no install checkpoint required |
</threat_model>
