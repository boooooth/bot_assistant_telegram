<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram user → bot process | Untrusted user text arrives via long polling; passed to OpenAI as a chat message (no shell/SQL/eval injection surface). |
| Bot process → OpenAI API (HTTPS) | API key leaves the process in the Authorization header (TLS handled by the SDK's httpx). |
| Bot process → Telegram API (HTTPS) | Bot token authenticates `getUpdates`/`sendMessage` (TLS handled by PTB's httpx). |
| Bot process → stdout logs | Risk of logging message bodies / secrets if logging is undisciplined. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Information Disclosure (privacy) | Logging strangers' message bodies / replies at INFO | mitigate | `main.py` logging logs chat id + status only, never message content or secrets (Security V7; RESEARCH anti-pattern line ~265). |
| T-01-06 | Information Disclosure | OpenAI key / Telegram token printed in logs or tracebacks | mitigate | Secrets only flow through `Settings`; never logged or hardcoded. Config errors name KEYS not values (inherited from Plan 01 T-01-04). |
| T-01-07 | Tampering | Prompt injection of the LLM by a user | accept | LOW impact in v1 — no tools, no memory, no data access; the model can only emit text (RESEARCH Security Domain). Fixed system prompt is the only control; revisit if tools/memory added (v2). |
| T-01-08 | Denial of Service / financial | Unbounded cost from public abuse (no rate limit / spend cap) | accept | Accepted v1 risk per PROJECT.md. Operational backstop = OpenAI dashboard billing cap (deferred, pre-launch). Rate limiting is COST-02 (v2). Not a Phase 1 code task. |
| T-01-09 | Denial of Service | A slow/erroring OpenAI call wedging the handler / crashing the bot | transfer | Friendly error handling + timeout robustness + concurrency is Phase 2 (REL-01/REL-02). Optional `AsyncOpenAI(timeout=60)` here is hygiene only, not the deferred handling. |

No HIGH-severity unmitigated threats. T-01-07/08/09 are explicitly accepted/transferred per locked project scope (public bot, cost risk accepted, reliability deferred to Phase 2).
</threat_model>
