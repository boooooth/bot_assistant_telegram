<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS environment → bot process | Secrets (Telegram token, OpenAI key) enter the process via `os.environ`; the only legitimate source for secrets. |
| Local filesystem / git → repo | `.env` (real secrets) must never cross into git; `.env.example` (blank) is the only committed config template. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `.env` with real Telegram token / OpenAI key committed to git | mitigate | `.gitignore` lists `.env` from commit #1 (Task 1); `.env.example` ships blank values only. Public-repo key leaks are scraped within minutes (RESEARCH Pitfall 2). |
| T-01-02 | Spoofing / Elevation | Leaked `TELEGRAM_BOT_TOKEN` → bot hijack | mitigate | Env-only secrets (config.py reads `os.environ`, never hardcoded); gitignored `.env`. Rotation via BotFather is the operational fallback if leaked. |
| T-01-03 | Tampering | npm/pip installs (`pip install -r requirements*.txt`) | mitigate | Packages are PyPI-official and pinned (PTB 22.7, openai 2.41.1, python-dotenv, pytest); RESEARCH.md "Package Legitimacy Audit" verdict OK for all — no `[ASSUMED]`/`[SUS]`/`[SLOP]`, so no blocking checkpoint required. |
| T-01-04 | Information Disclosure | Config error message leaking secret VALUES | mitigate | `ConfigError` names missing variable KEYS only ("Missing required environment variable(s): OPENAI_API_KEY"), never echoes values. |

No HIGH-severity unmitigated threats. All secret-handling threats (V14, the phase's dominant control) are mitigated.
</threat_model>
