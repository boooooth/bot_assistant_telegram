<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer machine → Docker build context | Files on disk (including a local `.env` with live secrets) cross into the Docker daemon and potentially into image layers |
| image layers → distribution (later: GHCR) | Anything baked into the image travels wherever the image goes; secrets in layers are effectively published |
| `.env` file → container runtime | Secrets injected at runtime via `env_file`; must never be persisted into the image |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | Docker build context / image layers | mitigate | `.dockerignore` excludes `.env` (Task 1); checkpoint Task 3 asserts no `/app/.env` exists in the built image |
| T-03-02 | Elevation of Privilege | container process user | mitigate | Dockerfile adds non-root `botuser` and `USER botuser` (Task 2); checkpoint asserts `id` is not uid=0 |
| T-03-03 | Tampering | dependency resolution / supply chain | mitigate | Pin `litellm==1.88.1` (Task 1) for reproducible builds; rely on litellm's transitive openai/httpx pins (no manual conflicting pins) |
| T-03-04 | Information Disclosure | `.env.example` template | mitigate | Template ships placeholder keys only (no values); correcting var names (Task 2) prevents misconfigured boots, not secret leakage |
| T-03-SC | Tampering | pip installs (litellm, ptb, python-dotenv) | accept | All three packages are pre-existing, already-installed, well-known PyPI packages (RESEARCH/STACK confirmed); pinning litellm reduces drift risk. No new/unaudited packages introduced this plan. |
</threat_model>
