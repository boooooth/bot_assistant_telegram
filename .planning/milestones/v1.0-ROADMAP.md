# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-06-16
**Phases:** 1–4
**Total Plans:** 8 (7 executed, 1 deferred)

## Overview

Delivered a public Telegram bot that accepts text messages from any user, forwards them to the OpenAI (ChatGPT) API via LiteLLM, and sends the reply back — running reliably in Docker on a Linux VPS with CI/CD gating deploys on green CI. Phases proceeded in a vertical MVP order: working bot first (Phase 1), then hardening (Phase 2), containerization (Phase 3), and automated delivery (Phase 4).

## Milestone Summary

**Key Decisions:**

- Used LiteLLM (not direct `openai` SDK) — provider switching via `LLM_MODEL`/`LLM_API_KEY` env vars without code changes
- One-shot replies, no conversation memory — simplicity for v1
- Polling over webhook — no domain/HTTPS needed; matches prior experience
- `python:3.12-slim` Docker base image — glibc compatibility, broad wheel support
- Non-root container user (`botuser`) — security hardening
- `.dockerignore` as the load-bearing DEP-03 control — secrets never enter build context
- CI/CD via `workflow_run` two-file structure (`ci.yml` unchanged, `deploy.yml` gated) — plan-authoritative, not RESEARCH single-file suggestion
- Deploy uses `--pull always --force-recreate` — guards against Compose bug #9259 (stale `:latest`)
- Dropped in-script `GITHUB_TOKEN` server login — revoked at job end, leaks into remote process list
- Handler tests use `asyncio.run()` idiom (not `@pytest.mark.asyncio`) — matches existing test style, zero new config

**Issues Resolved:**

- `deploy.yml` had `needs: []` — triggered simultaneously with CI, shipping on red CI. Fixed via `workflow_run` gate.
- `litellm` unpinned — non-reproducible builds. Fixed by pinning `==1.88.1`.
- `ruff`/`mypy` installed ad-hoc in CI but not in `requirements-dev.txt` — version drift risk. Fixed by pinning in dev requirements.
- In-script `GITHUB_TOKEN` server login — revoked at job end. Removed; server-side auth deferred to 04-03.

**Issues Deferred:**

- 04-03 live pipeline validation (GHCR pull credential + end-to-end run) — requires VPS not yet provisioned
- OpenAI dashboard billing cap — recommended before going public; not a code change
- `concurrent_updates=True` + connection pool sizing — research gap; validate empirically under load

**Technical Debt:**

- DEP-04 is code-complete but operationally unverified — deploy.yml will work but hasn't been proven on a real server yet
- No SHA-pinning on third-party GitHub Actions (using tag pins only) — supply-chain hardening deferred
