# Requirements Archive: v1.0 MVP

**Archived:** 2026-06-16
**Original defined:** 2026-06-11
**Core Value:** Send a message in Telegram, get a useful LLM reply back — reliably, 24/7.

---

## v1 Requirements — All Complete

### Core Messaging

- [x] **MSG-01**: Bot receives text messages from any Telegram user via long polling — ✓ v1.0 (Phase 1, PTB `run_polling()`)
- [x] **MSG-02**: Each text message is sent to the configured LLM as a one-shot prompt (no conversation history) — ✓ v1.0 (Phase 1, `litellm.acompletion` one-shot `[system, user]`)
- [x] **MSG-03**: The LLM's reply is sent back to the user in the same chat — ✓ v1.0 (Phase 1, `update.message.reply_text`)

### Commands

- [x] **CMD-01**: `/start` returns a short welcome explaining what the bot does — ✓ v1.0 (Phase 1, `START_TEXT` in prompts.py)
- [x] **CMD-02**: `/help` returns brief usage guidance — ✓ v1.0 (Phase 1, `HELP_TEXT` in prompts.py)

### LLM Integration

- [x] **LLM-01**: Bot calls the OpenAI (ChatGPT) API directly to generate the reply; model name configurable via env var, defaulting to `gpt-4o-mini` — ✓ v1.0 (Phase 1, LiteLLM with `LLM_MODEL` env var)

### Reliability

- [x] **REL-01**: On LLM/network error or timeout, bot replies with friendly error instead of going silent or crashing — ✓ v1.0 (Phase 2, `try/except` in handlers.py + 30s timeout)
- [x] **REL-02**: Slow LLM call for one user does not block replies to others — ✓ v1.0 (Phase 2, satisfied by PTB async architecture + asyncio)
- [x] **REL-03**: Exactly one polling instance per bot token — ✓ v1.0 (Phase 3, Compose `--force-recreate` stop-old-before-start-new)

### Deployment & Ops

- [x] **DEP-01**: Bot runs in Docker; same image locally and on server — ✓ v1.0 (Phase 3, hardened `Dockerfile` + `compose.yaml` dual build:/image:)
- [x] **DEP-02**: Bot runs 24/7 on Linux VPS, auto-restarts on crash or reboot — ✓ v1.0 (Phase 3, `restart: unless-stopped`)
- [x] **DEP-03**: Secrets via environment only — never committed or in image — ✓ v1.0 (Phase 3, `.dockerignore` excludes `.env`; server `.env` never committed)
- [x] **DEP-04**: Push to `main` triggers GitHub Actions pipeline that builds and deploys — ✓ v1.0 code-complete (Phase 4, `workflow_run` CI gate + `deploy.yml`); **live validation deferred** (04-03, no VPS at close)

### Quality & CI

- [x] **QA-01**: Automated `pytest` suite covers core message handling and OpenAI call path — ✓ v1.0 (Phase 4, `tests/test_handlers.py` + `tests/test_openai_client.py`)
- [x] **QA-02**: CI workflow runs ruff, mypy, pytest, Docker build on every push/PR; deploy only when CI passes — ✓ v1.0 (Phase 4, `ci.yml` + `deploy.yml` gated via `workflow_run`)
